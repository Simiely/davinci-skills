# resolve-flicker-fix —— 闪烁诊断与修复（先分型，再动手）

职责单一：判断"闪"属于哪一类、量化幅度、给出可执行的修复路径，并验证修完到底降了多少。不负责调色风格、不改剪辑结构。

## 什么时候用

- 用户说"第 N 段有闪烁""玻璃/水面/金属在闪""播放才看得见，单帧是干净的"。
- 调完色之后觉得"哪里在抖"，但说不清位置。
- 加过降噪但"感觉没用/更糊了"，需要判定到底有没有效。

## 反模式（务必避免）

1. **只看"块级最大差"就定位** —— 最大的块常常是**前景运动**（树枝、灯串、路人扫过镜头），不是噪点。实测踩过：把左下角运动的树枝当成闪烁源，白折腾一轮。
2. **只看整帧平均亮度** —— 高频噪点在 1080p 上被平均掉，整帧均值曲线会非常平滑（实测波动 <0.3 级），看不出问题。
3. **想用 LUT / 对比度 / 高光压制来修** —— 静态变换治不了时域问题。实测把高光压进肩部：闪烁只降 **−2.9% ~ −30.4%**，而白点从 255 崩到 **178**（画面发灰），完全划不来。
4. **用 ffmpeg `atadenoise` / `hqdn3d` 硬压** —— 对"小幅高频随机噪点"几乎无效：噪声指数 4.18 → **4.14 / 4.11**。
5. **一上来就加降噪** —— 先分型。切点处 1 帧纯黑属于**建线 bug**（见 `resolve-timeline-build`），加降噪只会让它更明显。
6. **把编码问题当素材问题** —— 先在**源素材**上测一遍：源里就有 → 素材/渲染问题；只有成片有 → 编码/渲染设置问题。

## A 主线（必做）

### A1 单文件扫描（定位 + 分型）

```powershell
py -3.12 skills\resolve-flicker-fix\scripts\flicker_scan.py --media "E:\src\clip.mp4" --range 600,810
```

输出三块，按顺序读：

| 输出 | 说明 | 判读 |
|---|---|---|
| 逐帧亮度曲线 | 96×54 灰度均值 | 出现 `亮度<6` 的孤立帧 → **黑帧**（建线 bug） |
| 局部热点（16×16 块） | 去趋势后的抖动 std | 值大不一定是噪点，**先怀疑运动** |
| 帧间差分序列 | 最抖块逐帧变化 | 连续 ±15 以上多半是运动；1~5 之间来回跳才像噪点 |

### A2 分型判据

| 类型 | 特征 | 修复去向 |
|---|---|---|
| 黑帧 | 单帧亮度 < 6，且落在切点上 | `resolve-timeline-build`（endFrame 排他） |
| 整帧亮度闪 | 全帧均值逐帧起伏 > 2 级 | 素材曝光/灯光频闪 → 时域降噪或重拍 |
| 局部高频噪点 | 块级抖动大，但改前/改后对比才见真章 | 见 A3 |
| 3D 玻璃/焦散闪烁 | 单帧干净、播放闪，集中于折射面 | 见 B1（渲染端）/ B2（后期） |

### A3 判定"降噪到底有没有用"（唯一可靠判据）

同一区域、同一帧段，比**逐像素帧间活动量**的比值（运动在两版里都一样，只有噪点会被吃掉）：

```powershell
py -3.12 skills\resolve-flicker-fix\scripts\flicker_scan.py ^
    --compare before.mp4 after.mp4 --range 600,810
```

判读：某块 `−15% ~ −25%` = 降噪确实作用到了这块；全画面 `−4%` 左右属正常（大部分画面本来就没噪点）；`±1%` = 降噪没打开或参数太弱。

## B 工具库（按需查）

### B1 3D 渲染（Cycles 类）的根治设置

| 设置 | 作用 | 代价 |
|---|---|---|
| 关掉"渲染时降噪"，改用**合成器 Denoise 节点跑序列** | 合成器能看相邻帧，比逐帧降噪稳定（OIDN 官方文档写明 RT filter "not temporally stable"） | 多一步合成 |
| 采样 256→512，Noise Threshold 0.01 | 噪点本身降到看不出来 | 渲染时间线性涨 |
| Light Paths → Caustics 关反射/折射焦散，或 Filter Glossy=10 | 玻璃焦散是 firefly 主源 | 少一点焦散光斑 |
| Clamping：Indirect ≈10 | 削掉孤立火点 | 极亮高光被压 |
| 玻璃 Transmission Roughness 0.02–0.05 | 折射变软，噪点骤降 | 玻璃略失清透 |
| 关掉 Animated Seed | 噪点图案锁死成"固定脏点"，不再闪 | 噪点重时更难看 |

### B2 只有成片时的后期路径（Resolve 内，需手动）

调色页选中片段 → `Alt+S` 加串行节点 → 右侧「降噪」面板 → 勾**时域降噪**：

| 参数 | 建议 | 原因 |
|---|---|---|
| 时域帧数 | 3（不够再 5） | 3 帧平均能吃掉约一半随机噪点；≥5 出现拖影 |
| 运动估计 | **更好** | 用"更快"会把运动误判成噪点，糊一片 |
| 降噪–亮度 | 15–20 | 按实测跳变幅度定（±18 级 → 阈值 ≥15 才吃得动） |
| 降噪–色度 | 20–25 | 可放宽 |
| 空域降噪 | 先关 | 问题在时间维度，空间降噪只让画面变糊 |

**API 限制（别再试）**：`Graph` 只有 11 个方法，**没有 AddNode**；降噪参数读不到也写不了，`GetToolsInNode` 只能读到 `['降噪']` 这个工具名。Fusion 侧同样没有降噪节点（实测注册表无 `Denoise/TemporalNR/TimeAverager/Trail/Echo/Median`）。⇒ 这一步必须由人在 UI 里点。

### B3 其它可测手段与实测结论

| 手段 | 实测效果 | 结论 |
|---|---|---|
| LUT 压高光 K=0.45/M=0.70 | 闪烁 −30.4%，白点 178 | 不可用 |
| ffmpeg `atadenoise` | 4.18 → 4.14 | 无效 |
| ffmpeg `hqdn3d` 时域 6 | 4.18 → 4.11 | 无效 |
| Resolve 节点「降噪」 | 玻璃区 −15%~−21% | 有效 |

## C 检查与沉淀

- 修复后**必须复测**：同一帧段、同一区域，给出改前/改后两个数字，别用"看起来好多了"结案。
- 如果用户说"还是闪"，先问他**具体秒数**——大概率是另一处，重新扫那一段，不要推翻已有结论。
